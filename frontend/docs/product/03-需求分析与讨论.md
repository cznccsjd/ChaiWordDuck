## 1. 产品愿景总结

### 1.1 核心定位

**拆词鸭**是第一款专注于**成人英语长单词（8字母+）深度记忆**的学习产品，通过基于维特根斯坦"语言游戏"哲学的五步学习法，让用户真正**理解、拆解、记住**长单词。

### 1.2 价值主张

| 维度 | 传统方法 | 拆词鸭方法 |
|------|----------|-----------|
| **学习方式** | 机械重复背诵 | 故事化深度理解 |
| **记忆策略** | 抽认卡 + SRS | 语言游戏 + 创意秘籍 + SRS |
| **词根拆解** | 工具书式列表 | 叙事化"组装故事" |
| **使用场景** | 单一例句 | 双场景对照（思辨场 vs 生活场） |
| **防错机制** | 事后纠错 | 预防式"犯规警告" |

### 1.3 目标用户

- **主要用户**：考试备考群体（大学生、考研、托福/雅思/GRE）
- **次要用户**：职场人士（阅读英文文献、商务沟通）
- **潜在用户**：终身学习者（有英语基础，想突破长单词瓶颈）

**用户画像示例**：
- 王小明，24岁，准备考研，英语基础良好（六级560分），但长单词总是记不住，用过墨墨背单词半年效果不佳
- 李华，28岁，外企职员，需要阅读英文技术文档，遇到 `implementation`、`authentication` 等长单词总是卡壳

### 1.4 商业模式

- **免费版**：每天学习3个长单词 + 基础复习功能
- **高级版**：¥9.9/月 或 ¥99/年（无限学习 + 高级功能）
- **企业版**：¥299/年（培训机构、企业批量采购）

## 2. MVP 范围定义

### 2.1 第一阶段：验证阶段（2周）

#### 目标
验证"五步语言游戏学习法"对用户记忆长单词的有效性。

#### 核心交付物

**1. 游戏手册制作**

| 要素 | 具体要求 |
|------|----------|
| **数量** | 20个高质量长单词"游戏手册" |
| **单词选择标准** | - 长度：8-15字母<br>- 词频：托福/雅思/考研高频词<br>- 难度分布：中等10个 + 困难10个<br>- 词性分布：名词8个、动词6个、形容词4个、副词2个 |
| **内容格式** | 每个手册包含：<br>1. 核心游戏定义<br>2. 双场景对照（思辨场 + 生活场）<br>3. 词根拆解 + 组装故事<br>4. 犯规警告<br>5. 通关秘籍（记忆技巧）<br>6. 标准例句（3-5个）|
| **质量标准** | - 词源准确性：100%（需权威词源词典验证）<br>- 故事趣味性：内测用户评分 ≥ 4.0/5.0<br>- 记忆技巧有效性：用户反馈"有帮助" ≥ 80% |
| **制作方式** | 人工撰写（第一阶段不使用 AI 生成，确保质量） |

**建议首批20个单词清单**（待确认）：
- 高频困难词：accommodation, serendipitous, entrepreneurship, bureaucracy, pharmaceutical
- 专业领域词：authentication, implementation, infrastructure, sustainability
- 抽象概念词：reconciliation, deterioration, consolidation
- 易混淆词：complement/compliment, affect/effect 相关长词

**2. 测试用户招募**

| 要素 | 具体要求 |
|------|----------|
| **招募渠道** | - 个人社交网络（朋友圈、微信群）<br>- 大学英语学习社群<br>- 知乎/小红书招募贴 |
| **用户数量** | 10-20人 |
| **用户筛选条件** | - 年龄：18-35岁<br>- 英语水平：CET-4以上或同等水平<br>- 当前痛点：正在备考或有长单词记忆困扰<br>- 时间承诺：愿意参与1周测试 + 反馈问卷 |
| **激励机制** | - 免费获得首批20个单词手册<br>- 赠送未来会员1个月<br>- 优秀反馈者额外奖励（如京东卡50元） |

**3. 反馈机制设计**

**测试流程**：
1. Day 0：用户收到20个单词手册（PDF/在线文档）
2. Day 1-5：用户每天学习4个单词（共20个）
3. Day 3：中期反馈问卷（学习体验、改进建议）
4. Day 7：记忆效果测试（单词拼写 + 使用场景选择题）
5. Day 7：最终反馈访谈（30分钟，深度了解用户感受）

**反馈收集工具**：
- 问卷：腾讯问卷/Google Forms
- 访谈：腾讯会议/Zoom（录音记录）
- 数据指标：
  - 记忆准确率（Day 7 测试正确率）
  - 学习完成率（完成学习的单词数/20）
  - 满意度评分（整体体验 1-5分）
  - 推荐意愿（NPS：是否愿意推荐给朋友）

**关键验证指标**：
- 记忆准确率 ≥ 70%（Day 7 测试）
- 满意度评分 ≥ 4.0/5.0
- NPS（净推荐值）≥ 50%
- 学习完成率 ≥ 60%

#### 关键问题待讨论

**Q1：手册呈现形式？**
- 选项A：PDF文档（精美排版，适合打印）
- 选项B：在线网页（响应式，方便手机查看）
- 选项C：微信小程序（最轻量，分享方便）
- **建议**：第一阶段使用选项B（在线网页），开发成本低，便于快速迭代

**Q2：单词学习顺序？**
- 用户自选 vs. 系统推荐？
- **建议**：第一阶段按照"易到难"固定顺序，减少用户决策成本

**Q3：如何控制测试质量？**
- 用户可能不认真学习或随意填写反馈
- **建议**：
  - 设置"学习打卡"机制（每天需确认学习完成）
  - 反馈问卷设置开放题，识别敷衍回答
  - 选择3-5名深度用户进行一对一访谈

### 2.2 第二阶段：MVP 开发（3-4周）

#### 目标
基于验证阶段反馈，开发可上线的最小可行产品（Web应用）。

#### 核心功能需求

**功能1：用户输入单词 → AI 生成"游戏手册"**

| 要素 | 详细需求 |
|------|----------|
| **功能描述** | 用户输入一个长单词（如 `accommodation`），系统自动生成符合五步学习法的游戏手册 |
| **技术实现方案** | **方案A（推荐）**：<br>- 前端：用户输入单词<br>- 后端：调用 GPT-4 API，使用预设 Prompt 生成手册<br>- 人工审核：生成后由人工快速审核（初期必需）<br><br>**方案B**：<br>- 预生成500-1000个手册存数据库<br>- 用户输入时直接返回（速度快但灵活性差） |
| **Prompt 设计关键** | 需要详细的 Prompt 模板，包含：<br>1. 五步结构要求<br>2. 语气风格（友好鼓励型）<br>3. 词源准确性要求<br>4. 输出格式（JSON/Markdown） |
| **质量保障** | - AI 生成后人工审核（初期100%审核）<br>- 用户可反馈"内容不准确"<br>- 建立"黄金手册"数据库（高质量人工手册优先展示） |
| **响应时间** | - 目标：< 10秒返回结果<br>- 显示"生成中..."加载动画 |
| **异常处理** | - 单词不在词典中：提示"未找到该单词，请检查拼写"<br>- AI 生成失败：返回基础词典定义 + 提示"详细手册生成中，稍后查看" |

**关键问题待讨论**：

**Q1：AI 模型选择？**
- GPT-4（质量最高，成本高）
- GPT-3.5-turbo（质量中等，成本低）
- 国产模型（如文心一言、通义千问）
- **建议**：初期使用 GPT-4（质量优先），达到500用户后评估成本优化

**Q2：如何确保词源准确性？**
- AI 可能"胡编"词源
- **建议**：
  - 接入权威词源 API（如 Etymology Dictionary）
  - 人工审核机制（初期必需）
  - 用户可举报错误（建立内容质量反馈系统）

**Q3：免费用户限制如何设计？**
- 免费用户每天3个单词：
  - 限制：每天凌晨0点重置次数
  - 提示："今日免费次数已用完，明天再来或升级高级版"
- **边界情况**：用户反复输入同一单词算不算次数？
  - **建议**：同一单词24小时内重复查看不计入次数（鼓励复习）

| 要素 | 详细需求 |
|------|----------|
| **功能描述** | 根据艾宾浩斯记忆曲线，系统提醒用户复习已学单词 |
| **触发机制** | - 学习新单词后第1天、第3天、第7天、第15天、第30天触发提醒<br>- 用户可自定义提醒时间（如每天晚上8点） |

## 3. 五步学习法详细需求

### 3.1 核心游戏：这是什么"局"？

#### 功能定义
用一句话概括单词的"本质使用场景"，而非传统定义。

#### 内容要求

| 要素 | 要求 |
|------|------|
| **字数限制** | 15-30字 |
| **语言风格** | 生动形象，避免术语堆砌 |
| **核心原则** | 回答"这个词在什么'游戏'中使用" |
| **反例** | ❌ `accommodation`：名词，住宿、调节<br>（这是词典定义，不是"语言游戏"） |
| **正例** | ✅ `accommodation`：这是一场"双向调整以达成共处"的协商游戏 |

#### 内容生成方式

**方案A（推荐）**：AI 生成 + 人工优化
- GPT-4 根据 Prompt 生成初稿
- 人工审核并优化语言
- 建立"优秀游戏定义"模板库

**方案B**：完全人工撰写
- 质量最高但效率低
- 仅用于"黄金手册"制作

#### 质量标准
- 用户测试反馈"帮助理解单词" ≥ 80%
- 不出现词典式术语（如"n. 名词"、"vt. 及物动词"）

---

### 3.2 游戏棋盘：双场景对照

#### 功能定义
展示单词在两种不同场景下的使用，让用户理解单词的"使用边界"。

#### 场景分类

| 场景类型 | 定义 | 示例 |
|----------|------|------|
| **思辨场** | 正式、抽象、学术、商务场景 | 哲学讨论、商务谈判、学术论文 |
| **生活场** | 日常、具体、口语场景 | 旅行、购物、聊天、日常交流 |

#### 内容要求

**每个场景需包含**：
1. **场景描述**（1-2句话）
2. **例句**（展示单词在此场景的使用）
3. **使用技巧**（可选，说明何时用此场景）

**示例**：
```
【思辨场】商务谈判中的"妥协调和"
例句：Both parties need to make accommodations to reach an agreement.
（双方需要做出妥协以达成协议）

【生活场】旅行中的"住宿"
例句：I need to book accommodation for my trip to Paris.
（我需要为巴黎之行预订住宿）
```

#### 场景选择逻辑

**如何判断一个单词适合哪种场景？**
- 通过语料库分析（如 COCA 美国当代英语语料库）
- 识别单词高频出现的场景类型
- AI 可辅助分析，但需人工验证

#### 数量要求
- MVP 阶段：每个单词2个场景（思辨场 + 生活场）
- 未来迭代：可扩展到3-4个场景

#### 关键问题待讨论

**Q1：某些单词只在正式场景使用（如 `pharmaceutical`），怎么办？**
- **建议**：标注"主要用于专业场景"，提供2个不同专业场景（如学术论文 vs. 新闻报道）

**Q2：场景例句从哪里来？**
- 选项A：AI 生成（需验证自然度）
- 选项B：从语料库提取真实例句
- 选项C：人工编写（最可控）
- **建议**：优先使用选项B（真实语料库例句），AI 生成作为补充

### 3.3 游戏溯源与拆解

#### 功能定义
展示单词的词根词缀拆解 + 词源演变故事。

#### 内容结构

**1. 词根拆解**
```
ac-  +  -commod-  +  -ation
向着      使适合       名词化
```

**格式要求**：
- 拆分规则：前缀 + 词根 + 后缀
- 每个部分附带中文释义
- 使用视觉化分隔（如 `+` 符号）

**2. 组装故事**
> 古罗马时代，主人（host）为客人（guest）调整房间和习惯，"使某物适合另一物"（ac- 向着 + -commod- 使适合），这种双向调整的行为后来演变为"调和、妥协"之意，也延伸出"提供住宿"的含义。

**故事要求**：
- 长度：50-100字
- 风格：叙事化，有画面感
- 准确性：基于权威词源词典（如 Oxford Etymology Dictionary）
- 趣味性：增加历史细节，让用户"脑补画面"

#### 数据来源

| 数据类型 | 来源 |
|----------|------|
| **词根词缀** | - 权威词根词缀词典<br>- 词源学 API（如 Etymonline API）<br>- 自建词根数据库 |
| **词源故事** | - Oxford Etymology Dictionary<br>- Merriam-Webster Etymology<br>- AI 生成后人工验证 |

#### 质量保障

**词源准确性验证流程**：
1. AI 生成初稿词源
2. 交叉验证至少2个权威词源词典
3. 人工审核（初期100%，后期抽样50%）
4. 用户可反馈"词源错误"（举报机制）

#### 关键问题待讨论

**Q1：如何处理词源不明确的单词？**
- 有些单词词源存在争议或不详
- **建议**：标注"词源有多种说法"或"词源不详"，提供最流行的版本

**Q2：拆解粒度如何控制？**
- 例如 `accommodation` 是否要进一步拆解 `commod-` 到拉丁语 `commodus`？
- **建议**：MVP 阶段拆解到"前缀-词根-后缀"即可，不过度追溯到古拉丁/古希腊

### 3.4 犯规警告

#### 功能定义
主动告知用户学习该单词时最容易犯的错误（拼写、用法、发音）。

#### 错误类型分类

| 错误类型 | 示例 | 优先级 |
|----------|------|--------|
| **拼写错误** | `accommodation` 常漏写一个 `m` 或 `c` | P0（最高） |
| **用法错误** | `affect` vs `effect` 混淆 | P0 |
| **发音错误** | `comfortable` 重音位置错误 | P1 |
| **搭配错误** | `make an accommodation`（正确） vs `do an accommodation`（错误） | P1 |

#### 内容要求

**格式**：
```
⚠️ 犯规警告：
最容易犯的错：拼写时漏掉一个 'm' 或一个 'c'
口诀："CC 看见 MM 住进房间"（两个c，两个m）
```

**要求**：
- 简洁明确（1-2句话）
- 提供记忆口诀（可选但推荐）
- 高亮显示易错部分

#### 数据来源

**如何识别"常见错误"？**

**方案A**：基于语料库分析
- 分析学习者语料库（如 Cambridge Learner Corpus）
- 识别高频错误

**方案B**：AI 推测 + 人工验证
- GPT-4 根据单词特征推测易错点
- 人工审核确认

**方案C**：用户贡献
- 用户可提交"我犯过的错误"
- 社区投票选出最常见错误

**建议**：MVP 阶段使用方案B（AI + 人工），后续开放方案C（用户贡献）

#### 关键问题待讨论

**Q1：如果单词没有明显易错点怎么办？**
- **建议**：可省略"犯规警告"，或提供通用提示（如"注意重音位置"）

**Q2：是否需要提供"易混淆词对比"？**

- **建议**：P1功能，MVP阶段可暂不实现

### 5.4 商业逻辑

#### Q7：免费版限制如何设计？
**问题**：既要吸引用户，又要推动付费转化。

**限制策略对比**：

| 限制方案 | 优点 | 缺点 |
|----------|------|------|
| **每天3个新单词** | 符合学习规律，不过度限制 | 可能不够紧迫感 |
| **总共免费20个单词** | 紧迫感强，转化压力大 | 可能过早赶跑用户 |
| **功能限制（如不能收藏）** | 用户可体验核心功能 | 影响用户体验 |
| **广告支持** | 用户可无限使用 | 影响体验，广告收入不稳定 |

**推荐方案**：**每天3个新单词 + 无限复习已学单词**
- 理由：
  - 符合学习规律（每天学3个长单词已足够）
  - 不影响复习（鼓励用户反复学习）
  - 有转化压力但不过度（重度用户会愿意付费）

**边界情况处理**：
- 已学单词可无限次查看（不计入次数）
- 收藏功能免费用户也可用（增加粘性）
- 次数在每天 00:00 重置
- 付费后立即解除限制
